# P2 Research Plan — UNSW-NB15 Network Traffic

Status: stage 6 draft (2026-10-06). All numbers come from `load_log.txt`, `verify_output.txt`
and `results.md`; regenerate them with the commands in section 7.

## 1. Problem

Intrusion-detection research usually jumps straight to classifiers. Before that, a simpler
question: do attack flows have a measurable behavioral fingerprint (bytes, duration, service),
and which apparent patterns are artifacts of how the benchmark was built?

## 2. Data collection — split files without headers

- Source: UNSW-NB15 (UNSW Canberra Cyber Range Lab, 2015), Kaggle mirror `mrwellsdavid/unsw-nb15`. See `data/SOURCE.md`.
- Four headerless CSV parts (700,001 + 700,001 + 700,001 + 440,044 = 2,540,047 flows, 586 MB),
  plus a separate feature-definition file (49 columns) and an event list.
- Collection challenge: the parts cannot be read meaningfully on their own; column names and types live in a different file.

## 3. Database construction — metadata-driven schema and label repair

- `feature_def` table is loaded from `NUSW-NB15_features.csv`; `load.py` generates the `flow` table DDL from it (`src/schema_generated.sql`).
- Dimensions: `host` (49 IPs), `protocol` (135), `service` (13), `conn_state` (16), `attack_category` (9).
- Label repair, recorded in `attack_label_variant`: 13 raw spellings -> 9 families
  (`" Fuzzers "`, `" Fuzzers"` -> Fuzzers; `"Backdoor"`, `"Backdoors"` -> Backdoors; trailing/leading spaces on Reconnaissance, Shellcode).
- Port repair: hexadecimal values (`0xcc09`) decoded; 9 `'-'` values stored as NULL.
- Indexes built after the bulk load (label, family, service, source host, start time).
- Verification: 0 foreign-key violations; label and family agree on every row (0 mismatches).

## 4. Methods

| H | Question | Test | Why |
|---|---|---|---|
| H1 | Attack vs normal bytes / duration | Mann-Whitney U + rank-biserial r | heavy-tailed, two groups |
| H2 | Bytes across 9 attack families | Kruskal-Wallis + epsilon^2 | 9 groups, heavy-tailed |
| H3 | Service x attack | Chi-square + Cramer's V | categorical x binary |
| H4 | Attack flows by source host | Gini, top-3 share | concentration |
| H5 | Hour of capture x attack | Chi-square + Cramer's V | categorical x binary |

## 5. Results

| H | Result | Effect | Reading |
|---|---|---|---|
| H1a | bytes: p < 0.001 | r = -0.73 | large: median 114 (attack) vs 1,684 (normal) bytes |
| H1b | duration: p < 0.001 | r = -0.55 | large: attacks are near-instant |
| H2 | p < 0.001 | epsilon^2 = 0.76 | very large: families have distinct byte profiles (Generic 114 ... Worms 1,302) |
| H3 | p < 0.001 | V = 0.30 | moderate: DNS 27% attack vs SSH 0.04% (services with < 200 flows not interpreted) |
| H4 | Gini = 0.93 | top-3 = 92.9% | 4 of 43 source hosts sent all attacks |
| H5 | p < 0.001 | V = 0.30 | attack share 0% - 28.8% by hour |

H4 and H5 are testbed artifacts. Every attack flow comes from four hosts, 175.45.176.0-3
(verified in the DB). The hourly pattern is most likely the attack generator's run periods; the
official page does not document a schedule, so this is an inference to confirm from the
dataset papers. Both results describe the benchmark, not real networks, and are reported as a
caution for anyone using this dataset.

## 6. Limitations

- Testbed traffic: "a hybrid of real modern normal activities and synthetic contemporary attack
  behaviours" generated by the IXIA PerfectStorm tool (official page); flow timestamps are from 2015.
- 526,427 rows are exact repeats of another row on the key fields (`verify_output.txt`); tests use all rows as published. A deduplicated re-run is a planned sensitivity check.
- Total rows 2,540,047 vs 2,540,044 in the official description; the 3-row difference is not explained yet.
- Hour is computed in UTC from `stime`.
